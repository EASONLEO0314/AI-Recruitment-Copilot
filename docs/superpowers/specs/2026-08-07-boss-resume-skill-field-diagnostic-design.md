# BOSS 简历技能字段安全诊断设计

日期：2026-08-07

## 1. 问题与证据

真实授权样本已经通过 Vue 2 `resumeInfo` 精确读取工作、教育和项目经历，但界面显示“缺少技能”，而 BOSS 简历正文存在“专业技能”栏目。

当前能力结果只命中 `geekBaseInfo`、`geekWorkExpList`、`geekProjExpList`、`geekEduExpList`，没有命中现有白名单中的 `skillTagList`。重新静态检查公开参考插件后，确认其技能实现也只读取 `skillTagList`；因此照搬参考实现不能解决当前样本。

根因边界：可以确认技能不在当前已支持的 `skillTagList`；尚不能确认技能的真实字段名或数据形态。正式映射前不得猜测字段路径。

## 2. 选择的方案

采用两阶段方案：先运行一次无正文的顶层 schema 诊断，再根据真实结果扩展固定白名单。

不采用以下方案：

- 不直接猜测 `geekSkillList`、`skillList` 等字段名，因为没有现场证据。
- 不优先解析“专业技能”DOM 标题，因为当前简历正文存在 Canvas/特殊渲染，现有 DOM 来源没有读到该栏目。
- 不启用 OCR；OCR 仍保留为 Vue 与 DOM 都无法提供技能时的后续兜底。

## 3. 数据流

1. 用户手动打开当前候选人简历并点击“读取当前简历”。
2. 扩展继续在当前 tab 的全部 frame、MAIN world 中定位可见简历根和已确认的 `resumeInfo`。
3. 在现有固定能力信息之外，通过自有属性描述符读取 `resumeInfo` 的顶层可枚举键名；访问器属性不调用 getter，统一标记为 `other`。
4. 对数据属性只生成：安全键名、固定类型标签、受限数组长度；不返回字符串、数字或对象内容。
5. Service Worker 对结果做严格格式校验和数量限制后传给悬浮窗。
6. 悬浮窗仅显示 schema 诊断；用户提供不含候选人正文的诊断结果。
7. 根据现场证据选择一个确切技能字段，另行增加失败测试和固定白名单映射。

## 4. 安全边界

- 仍然只由用户点击触发一次，不轮询、不重试、不自动刷新。
- 最多返回 40 个顶层字段；键名必须匹配 `^[A-Za-z_$][A-Za-z0-9_$]{0,63}$`。
- 类型只允许固定枚举：`array`、`object`、`string`、`number`、`boolean`、`null`、`undefined`、`other`。
- 数组只返回 `0..50` 的截断长度；不访问数组元素。
- 不递归遍历对象，不调用任意对象的 `toJSON`、`toString` 或 getter 值解析。
- 不返回候选人姓名、技能内容、简历正文、Cookie、Token、请求头或浏览器存储。
- 不新增网络请求、自动点击、滚动、聚焦、导航、输入或发送。
- schema 结果仅存在于当前悬浮窗内存，不写入持久化存储和业务日志。

## 5. 界面与错误处理

诊断结果附加在现有“MAIN world 能力探针”区域，显示“字段名 · 类型 · 数量”。现有 Vue 精确简历结果继续正常展示，不改动 92% 演示评分。

若顶层键读取失败、结果越界或校验不通过，使用固定错误码并丢弃整段 schema 诊断；不得向界面或日志透传异常原文。

## 6. 测试设计

实现前先增加失败测试，覆盖：

- 只输出顶层键名、固定类型与数组长度；
- 不输出字符串、数字或嵌套对象的值；
- 键名、字段数量和数组长度受限；
- getter 抛错、循环对象和非法键名不会泄漏或中断读取；
- Service Worker 拒绝未知类型、额外字段和越界结果；
- 页面只在用户点击后显示 schema 信息；
- 不产生点击、滚动、存储或网络副作用。

## 7. 验收标准

第一阶段通过条件：用户重新加载扩展并点击一次后，可以看到 `resumeInfo` 的安全顶层 schema；诊断中不出现任何候选人字段值，且页面没有自动行为。

第二阶段通过条件：根据诊断确认确切技能字段，加入固定映射后，技能内容与 BOSS“专业技能”栏目一致；原有工作、教育、项目映射和演示评分标识不回退。最终准确率仍按既有五个匿名授权样本标准计算。
