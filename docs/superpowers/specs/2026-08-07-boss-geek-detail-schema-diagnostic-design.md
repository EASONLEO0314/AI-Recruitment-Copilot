# BOSS `geekDetailInfo` 下一层安全诊断设计

日期：2026-08-07

## 1. 现场证据与根因边界

用户在授权候选人页面手动点击“读取当前简历”后，`resumeInfo` 顶层 schema 成功返回 40 个字段。结果中存在 `geekDetailInfo`，但不存在现有技能路径 `skillTagList`；因此当前“缺少技能”并非界面显示错误，而是现有白名单没有命中真实技能路径。

顶层字段均显示为“其他”，原因是 BOSS 当前 Vue 2 页面把这些响应式字段暴露为访问器属性。顶层诊断为避免调用未知 getter，只能确认键名，不能确认 `geekDetailInfo` 内部结构。公开代码检索也没有提供可验证的内部字段结构，正式技能映射仍不得猜测字段名。

## 2. 选定方案

采用单容器、单层诊断：继续只在用户手动点击“读取当前简历”时，读取固定白名单字段 `resumeInfo.geekDetailInfo`，并仅枚举该对象的直接子字段结构。

本轮不检查 `geekQuestInfoVO`、`multiGeekVideoResume4BossVO` 或其他容器，不解析技能正文，不新增正式技能映射。若 `geekDetailInfo` 的下一层仍没有可验证技能字段，再根据新证据决定是否检查另一个固定容器。

## 3. 数据流

1. 用户手动点击一次“读取当前简历”。
2. MAIN world 读取器按现有逻辑定位当前可见简历根和 `resumeInfo`。
3. 读取器仅通过现有受保护读取函数访问固定键 `geekDetailInfo` 一次。
4. 若结果是对象，只枚举它的直接自有字段；不递归进入孙级对象。
5. 每项仅生成固定路径、固定类型与受限数组长度，例如：

```text
geekDetailInfo.skillTagList · 数组 6
geekDetailInfo.professionalSkill · 字符串
```

6. Service Worker 严格校验后，将诊断传给当前悬浮窗；界面只显示结构信息。
7. 用户回传该结构截图后，再依据确切字段另行设计技能映射。

## 4. 安全与数量边界

- 仍然只由用户点击触发，不轮询、不自动重试、不刷新页面。
- 只允许容器名 `geekDetailInfo`，拒绝任意动态路径。
- 最多返回 40 个直接子字段；字段名必须匹配 `^[A-Za-z_$][A-Za-z0-9_$]{0,63}$`。
- 类型只允许 `array`、`object`、`string`、`number`、`boolean`、`null`、`undefined`、`other`。
- 数组只返回截断到 `0..50` 的长度，不读取数组元素。
- 子字段访问器只标记为 `other`，不调用 getter。
- 不输出字符串、数字、对象或数组内容，不调用任意 `toJSON`、`toString`。
- 不读取 Cookie、Token、请求头、浏览器存储，不新增 BOSS 网络请求。
- 不点击、聚焦、滚动、输入、导航或发送任何内容。
- 诊断只保存在当前悬浮窗内存，不写入持久化存储或业务日志。

## 5. 错误处理

- `geekDetailInfo` 不存在、getter 抛错或结果不是对象：顶层读取结果仍保留，下一层诊断为空。
- 属性描述符读取失败：丢弃整个 `geekDetailInfo` 下一层诊断，不透传异常原文。
- 任一跨边界字段不符合固定格式、数量或长度限制：Service Worker 拒绝该次 ready probe，界面显示现有固定安全错误，不展示原始对象。

## 6. 测试与验收

实现前先增加失败测试，覆盖：

- 只读取固定 `geekDetailInfo`，不检查其他顶层容器；
- 只输出直接子字段名、固定类型和数组数量；
- 不输出技能正文或其他候选人值；
- 子字段 getter 不被调用；循环对象、非法键名和超限字段不泄漏；
- 跨边界校验拒绝未知容器、未知类型、重复路径和越界长度；
- 界面只接受固定 `geekDetailInfo.<safe-key>` 诊断格式；
- 完整 warning 数量仍受明确硬上限约束。

本轮通过条件：重新加载扩展并手动读取同一候选人后，悬浮窗出现 `geekDetailInfo` 的下一层结构，且不包含任何候选人正文，也没有自动页面行为。

本轮不以“技能已读取”为通过条件。只有下一轮根据真实结构加入固定技能映射，并与 BOSS“专业技能”栏目人工核对一致后，才能宣布技能问题修复。
